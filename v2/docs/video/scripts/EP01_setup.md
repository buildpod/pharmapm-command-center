# Episode 1 — Set up a project you can defend

## The principle

Before execution starts, authority and scope have to be explicit. Who sponsors
this, what is in scope, what does done look like, and what date have we
committed to?

In the standards this is the project charter — the document that authorises the
work. In practice it's the difference between a project that can be governed and
one that can only be argued about.

## Why it goes wrong

Most teams start executing from a task list nobody formally agreed.

There's a kickoff, some slides, an assumed date. Work begins. And because
nothing was frozen, when the project slips there is no agreed original to
measure the slip against. Six months later, "we were always going to finish in
Q3" is a matter of memory, not record.

The failure isn't the slip. It's the absence of an agreed starting point.

## How PharmaPM implements it

Setup captures the project facts first, then generates the structure — and
shows you what it will create *before* anything exists.

Critically, the go-live date you enter becomes the frozen commitment. Everything
afterwards is measured against it. If it moves later, the system records who
moved it and why. We'll come back to that in episode nine.

## Doing it

Click **New Project**. Setup runs in four steps.

**Step one, Discover.** Project name, client, the start date, the go-live date,
methodology, and the regions involved. These aren't administrative fields —
dates drive the schedule engine, regions drive the working calendar, and the
go-live becomes your commitment.

**Step two, Choose source.** Four honest ways in. Create from a pharma playbook
when the project resembles a known rollout pattern. Import an existing plan from
Microsoft Project or Excel if one already exists. Reuse a saved template. Or
start with a blank skeleton and build it yourself.

For a first project, the playbook route shows the most.

**Step three, Shape model.** You see the structure that will be generated —
milestones, workstreams, tasks, risks, documents, budget lines — and you tune
it. If a section isn't ready, defer it. A deferred section simply isn't created;
you can add it later.

**Step four, Validate.** Read what will be created. This is the last checkpoint
before records exist. Then press **Create Command Center**.

## What good looks like

The dashboard opens with a guided review banner and a readiness checklist that
reads something like "four of seven ready".

That number is computed from your actual records — it is not a checklist you
tick. Items go green when the underlying thing is genuinely true: the charter
exists, milestones have owners, tasks link to milestones, budget lines are
present.

If it says four of seven, three real things need attention.

## Common mistakes

The big one is treating the generated plan as the truth.

It isn't. A playbook gives you a professionally-shaped starting point based on
how projects like yours usually run. It knows nothing about your vendor, your
team, or your constraints. It is a draft.

Episode two is where it becomes yours — and until that review is done, treat
every number the dashboard shows as provisional.

The second mistake is rushing step one. A wrong go-live date means you've frozen
the wrong promise, and every measurement afterwards is against a target nobody
actually agreed.
