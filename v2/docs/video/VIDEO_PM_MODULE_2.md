# PM Module 2 — The weekly rhythm: run, absorb, report

> **NotebookLM instruction (paste into Video Overview → Customize):**
> Audience: project managers already using the command center (they've seen
> Module 1). Tone: calm, practical, peer-to-peer. Length: 6–8 minutes. Follow
> the narration sections strictly and in order; do not invent features not
> described here.

**Goal:** the PM's repeatable weekly loop — update, absorb a slip with
governance, and produce a defensible report.

---

## Scene 1 — The loop (0:00–0:40)

A command center is only alive if the weekly rhythm is cheap: update what
happened, absorb what changed, report what's true. This module walks that loop
once, the way a real week goes — including the part where a date slips.

## Scene 2 — Updating work (0:40–2:00)

Tasks update in place: click a status badge to advance it, click a progress
bar to edit it. Each task can carry a budget — and when every task has one,
the confidence score weights earned value by budget, so a £200k task at 100%
counts for far more than a £2k task. That closes the classic gaming gap where
finishing ten trivial tasks looks like real progress.

Claimed progress is also cross-checked: when what you claim disagrees with
what the records show — dates slipping, dependencies blocked — the integrity
check flags the gap, and the report carries the caveat. The tool assumes
optimism, not dishonesty; it just refuses to hide the difference.

## Scene 3 — A date slips (2:00–3:45)

Move a task's due date and the schedule impact review opens BEFORE anything
saves: which downstream tasks shift, which milestones move, whether the
committed go-live is breached, and whether anything collides with a hard
window like a regulatory freeze.

You choose explicitly: adjust the plan, or accept the slip. Accepting is not a
quiet edit — it records a decision with your name on it, writes the audit log,
and shows up in this week's report under "Accepted changes". Slips still
happen; they just can't happen silently.

## Scene 4 — The baseline stays honest (3:45–4:45)

The Milestones page carries the commitment banner: the go-live date that was
frozen when the project committed, versus where the forecast is now. If a
re-baseline is genuinely needed, it's done there — with a reason, recorded,
visible in the report's "Baseline changes" section. The target can move, but
it can never just wander.

## Scene 5 — Reading the signals (4:45–5:45)

Delivery Signals is where the confidence score explains itself: the arithmetic
is shown with your live values — cost efficiency, schedule pace, forecast
headroom — and each active signal carries why it matters, the next action, and
trace links to the exact records behind it. Capture a trend point each week
and the report shows direction of travel: improving, declining, or flat.

## Scene 6 — The report writes itself (5:45–7:00)

Reports pull from the same records — nothing is retyped, so the pack can't
contradict the screens. Weekly Status for the working level; the Steering
Committee brief for executives; Workstream detail for leads. Each prints to
PDF and exports to Excel, and each includes the governed history: accepted
changes, baseline changes, the integrity caveat if progress looks optimistic,
and the trend since last week.

## Scene 7 — Close (7:00–7:30)

That's the rhythm: update in clicks, absorb slips as governed decisions, and
let the report assemble itself from evidence. The week costs minutes — and
every claim in the pack survives the question "says who?".
